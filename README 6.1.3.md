# Практична робота 6.1 · Базовий State Management

**Дисципліна:** Програмування для мобільних платформ  
**Варіант 3:** Налаштування теми для читанки  
**Назва застосунку:** «Тиха сторінка»  
**Технології:** Flutter SDK і Dart. Пакети керування станом не використовуються.

## Мета та результат

Навчитися відокремлювати локальну чернетку інтерфейсу від застосованих налаштувань,
піднімати спільний стан до предка та надавати його через InheritedNotifier.
Підготовлено читанку з довгим навчальним текстом і окремим екраном налаштувань.

Реалізовано:

- світлу, темну та системну тему;
- п’ять акцентів: «Ліс», «Океан», «Лаванда», «Теракота», «Бірюза»;
- слайдер розміру тексту 12–24 з початковим значенням 18;
- попередній перегляд чернетки теми, акценту та розміру;
- застосування розміру через onChangeEnd, після відпускання слайдера;
- застосування теми та акценту окремою кнопкою;
- скидання до системної теми, першого акценту та розміру 18;
- дві версії архітектури з тегами Git та тести.

Якщо вийти з налаштувань без натискання «Застосувати тему й акцент», ці дві
чернетки буде відкинуто. Розмір, який уже застосовано після відпускання слайдера,
залишається. Застосовані параметри зберігаються в пам’яті до повного перезапуску;
постійне збереження на диску не входить до цього завдання.

## Етап 1: підняття стану

```bash
git switch --detach stage-1-lifting
flutter pub get
flutter run -d chrome
```

ReaderApp — спільний предок і власник ThemePreferences та TextPreferences.
Методи зміни викликають setState. Налаштування й колбеки передаються конструкторами
через ReaderScreen до SettingsScreen. ReadingBody отримує розмір тексту параметром.
Чернетка теми, акценту й слайдера залишається у локальному State SettingsScreen.

Зміна шрифту на цьому етапі викликає setState спільного предка й перебудовує
також MaterialApp. Це початкова архітектура для порівняння з другим етапом.

## Етап 2: два незалежні джерела сповіщень

```bash
git switch --detach stage-2-inherited
flutter pub get
flutter run -d chrome
```

ThemeSettings і TextSettings — два окремі ChangeNotifier.
ThemeScope та TextScope — окремі InheritedNotifier зі статичними of(context).
Обидва надаються над MaterialApp, щоб бути доступними і маршруту налаштувань.

AppThemeBuilder читає лише ThemeScope.of(context) і формує theme, darkTheme,
themeMode для MaterialApp. ReadingBody читає лише TextScope.of(context).
Тому сповіщення TextSettings не підписує й не перебудовує AppThemeBuilder.

SettingsScreen отримує початкову чернетку через read(context), який не реєструє
залежності. Він викликає команди моделей, але не підписаний на TextSettings.
Зміни прев’ю під час руху слайдера відбуваються через локальний setState.
Передавання спільних налаштувань і колбеків через проміжний ReaderScreen прибрано.

Повернення до основної гілки: `git switch main`.

## Як застосовуються параметри

`onChanged` оновлює `_draftSize` через setState. Це переміщує слайдер і змінює
PreviewCard. `onChangeEnd` передає значення у TextSettings.setFontSize.
Модель перевіряє межі 12–24 та відкидає NaN і нескінченність.

Тема й акцент до натискання кнопки впливають лише на PreviewCard. Для системного
режиму прев’ю використовує MediaQuery.platformBrightnessOf(context).
Застосунок використовує ThemeMode.system, а не одноразово визначену яскравість.

Усі кольори інтерфейсу походять із ThemeData та ColorScheme.fromSeed. П’ять
явних seedColor визначають лише варіанти початкової палітри; фон і текст не
мають окремо заданих незмінних кольорів. Розмір читання не змінює глобальну
textTheme, тому кнопки й AppBar не збільшуються разом зі статтею.

## Структура коду

- `lib/main.dart` — створення ThemeSettings і TextSettings, розміщення scopes, dispose.
- `lib/models/theme_preferences.dart` — незмінні параметри теми, палітра, генератор ThemeData.
- `lib/models/text_preferences.dart` — незмінні параметри тексту.
- `lib/models/article.dart` — const-модель та довгий навчальний текст.
- `lib/state/theme_settings.dart`, `text_settings.dart` — моделі зі сповіщеннями.
- `lib/state/theme_scope.dart`, `text_scope.dart` — of(context) і read(context).
- `lib/screens/reader_screen.dart` — екран читання та перехід у налаштування.
- `lib/screens/settings_screen.dart` — локальні чернетки, слайдер, застосування, скидання.
- `lib/widgets/app_theme_builder.dart` — створення MaterialApp на основі ThemeSettings.
- `lib/widgets/reading_body.dart` — текст, залежний від TextSettings.
- `lib/widgets/preview_card.dart` — ізольований попередній перегляд.

ReaderApp звільняє обидві моделі у dispose(). Контролерів введення,
StreamSubscription та таймерів у цьому варіанті немає. Підписки InheritedNotifier
обслуговує сам Flutter.

## Журнал перебудов

У ключових build є debugPrint. Наведені фрагменти — **очікувані результати**,
не фактичні логи виконання.

Коли змінюється тільки застосований розмір тексту:

```text
build: ReadingBody
```

Коли застосовується інша тема:

```text
build: AppThemeBuilder
```

Після зміни теми можуть також перебудовуватися віджети, залежні від Theme.of(context),
зокрема ReadingBody та PreviewCard. Це очікувано: їхні кольори змінилися.

Під час руху слайдера очікуються SettingsScreen і PreviewCard через локальний
setState. AppThemeBuilder не повинен з’являтися в журналі від самої зміни шрифту.
Відмінність між локальним прев’ю та застосуванням перевіряє test/app_test.dart.
Окремий test/rebuild_test.dart ізолює сповіщення моделі та перевіряє відсутність
перебудови AppThemeBuilder після зміни розміру.

InheritedNotifier не виконує автоматичного вибору полів моделі. Ізоляція
досягнута двома моделями й двома окремими залежностями.
Фактичний журнал після запуску додайте в [docs/rebuilds.md](docs/rebuilds.md).

## Висновок

Підготовлено два способи керування спільним станом. Перший використовує
конструктори, колбеки й setState спільного предка. Другий розділяє тему та текст
між незалежними ChangeNotifier. Локальні чернетки забезпечують попередній перегляд,
а окремі підписки дозволяють змінювати текст без перебудови MaterialApp.
Працездатність і фактичні перебудови потрібно підтвердити локальними перевірками.
